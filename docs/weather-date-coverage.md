# 按日期查询天气

状态：Issue #4 的工具切片，依赖出行工作台 PR #12；已增加原始天气依据和降水活动类别提示，结构化天气卡、具体地点备选及行程草稿切换仍待实现。

## 调用契约

CLI 与真实模型模式的 Web 工作台复用同一个 `weather` 工具，无需额外开关；仍需配置天气凭证与 API Host。演示模式不调用天气。

```json
{"city":"杭州","date":"2026-10-01"}
```

- `date` 可选，必须是有效的 `YYYY-MM-DD`，表示目的地的预报日期；相对日期需先明确成具体日期。
- 提供 `date` 且省略 `type` 时使用 `forecast`；显式 `type: "now"` 与日期冲突，在网络请求前拒绝。显式 `forecast` 可与日期一起使用。
- 没有 `date` 时保持既有行为：默认实况；`type: "forecast"` 返回三天接口实际提供的全部日预报。
- `date` 在工具内部匹配 Provider 返回的 `daily[].fxDate`，不作为历史天气参数发送，不扩大订阅或预报天数。

## 日期与证据

预报文本附带来源 `QWeather`、实际 Location ID、获取时间（UTC）、Provider 的 `updateTime` 原文及排序后的实际可用日期。获取时间表示本次收到响应，不等于预报生成时间；Provider 未返回更新时间时明确标注无法确认新鲜度。

指定日期仅匹配同一天的数据。例如 Provider 只返回 9 月 17 日和 19 日，查询 18 日也返回“天气未知”，不能仅根据起止日期认为已覆盖。未覆盖时保留证据元数据，省略其他日期的天气与温度，避免被当作目标日期的依据。响应中日期非法/重复、温度或天气描述为空时拒绝使用；Provider/HTTP 错误和取消继续沿用原错误路径。

本切片不判断数据是否已超过新鲜度阈值、不补齐缺失数据、不获取历史天气，也不保证模型一定遵守工具结果。尚未提供候选地点确认界面或独立天气卡片；已有下述原始天气依据折叠区域。

## 地点澄清（2026-09-21，Issue #20）

城市搜索返回多个不同 Location ID 时，工具返回包含名称、行政区、国家和 ID 的澄清错误，停止实况与预报请求。模型应先询问用户，再将选定 ID 作为 `city` 重试；即使某候选名称与输入完全相同，也不能忽略其他同名或模糊候选。返回结果中的精确 ID 可以选择非第一项；重复 ID 只算一个地点，任一候选缺少 ID 则拒绝使用。

采用保守的多候选澄清策略，可能增加一次交互。工具不持久化用户确认，也无法证明模型确实征求了选择；这不是服务端强制审批流程。行政区字段及 Location ID 输入语义依据 [QWeather City Lookup 官方文档](https://dev.qweather.com/en/docs/api/geoapi/city-lookup/)（2026-09-21 核对）。本地固定 HTTP 样例验证两种查询模式及零天气请求，不代表真实供应商联调。

## 验证

### 降水备选（2026-09-22，Issue #22）

每个返回日期现在包含 `daily[].precip` 的预报总降水量（mm）及独立标为“应用规则”的活动提示。有降水时提供室内展览/阅读休息等类别，尚未结合具体场馆、偏好或交通校验；零降水不等于适合户外，不能据此忽略温度、风力与预警。缺失、非法、负数、NaN/Inf 降水不生成活动建议，未覆盖日期不借用其他天的建议。

活动提示只使用更新时间有效、不晚于获取时间且年龄不超过 6 小时的预报；6 小时是本应用的规划阈值，不是供应商 SLA，也不改变原始预报是否展示。不在此窗口内时保留预报证据并要求刷新；该规则不代替地点当地预警、出行安全或数据真实性验证。字段与单位依据 [QWeather 日预报文档](https://dev.qweather.com/en/docs/api/weather/weather-daily-forecast-webapi-v7/) 和 [单位文档](https://dev.qweather.com/en/docs/resource/unit/)（2026-09-22 核对）。

完整工具轮次回归验证降水与规则来源保存在历史中，已有前端天气依据折叠区可查看原文。该提示不是模型生成的个性化行程，不修改行程草稿，也不保证模型会正确采用规则。

2026-09-19：工作台在成功轮次的最终回答旁增加“天气依据”折叠区域，展示该轮按 tool_call_id 配对的 weather 原始结果。孤立结果、其他工具、跨轮旧 ID 不作为天气依据；所有文本经 Vue 转义。刷新可从已保存历史还原，切换会话不保留上一会话依据。结果可能包含未知或执行错误，不是“已核实”的标签；尚未做结构化气象卡片或模型引用正确性检查。

浏览器回归使用明确的历史 API 固定样本，覆盖关联、刷新、会话切换、HTML 字符串转义和 390px 窄屏。它验证展示逻辑，不等于真实天气/模型端到端联调。

```bash
go test ./internal/tool/builtin -run TestWeather
go test ./internal/trip -run TestTripWeatherDateIsPreservedThroughToolTurn
```

固定本地 HTTP 数据覆盖首尾日期、范围前后、中间缺日、闰年、乱序、非法/重复日期、缺失字段和取消。工作台 HTTP 集成测试通过模拟模型触发真实工具代码，确认日期参数出现在模型工具定义中，未覆盖结果回灌模型，成功回合的工具调用与结果配对持久化。模拟模型的最终措辞不作为真实模型遵从度的证据；没有使用真实付费天气或模型账号。

## 天气观测证据（2026-09-18，Issue #14）

`type: "now"` 现在输出“天气观测”及来源、Location ID、获取时间、API 更新时间和观测时间。获取时间是本次收到响应的本机 UTC 时间，`updateTime` 是 API 更新，`now.obsTime` 是实际观测时间；三者不可互相替代。按获取时间减观测时间显示年龄，较旧观测不会因重新获取而变新。

Provider 时间支持带时区的秒精度 RFC3339 及官方例子中的分钟精度。缺失或非法时间明确未知，未来时间标为时钟/数据异常；异常观测年龄保持未知，不以负数表示新鲜。原气象字段仍保留，作为该次观测记录，而非当前状态保证。

本切片不设通用过期阈值，不保证 API 更新时间与观测时间一致，也不证明真实服务联调成功；固定 HTTP 和时钟样例覆盖时区、旧观测及异常字段。字段语义参见 2026-09-18 核对的 [QWeather Weather Now v7 文档](https://dev.qweather.com/en/docs/api/weather/weather-now-webapi-v7/)。

### Provider 迁移

2026-09-17 核对 [QWeather 城市版日预报文档](https://dev.qweather.com/en/docs/api/weather/weather-daily-forecast-webapi-v7/)：当前 `/v7/weather/{days}` 支持 `3d` 等天数参数，`fxDate` 是预报日期，`updateTime` 是 API 更新时间。官方已提示 v7 将弃用，并指向 v1。本次保持既有 v7 配置兼容；后续需独立迁移经纬度、认证和响应结构，结合用户订阅联调后再替换，不能直接把新路径套到旧解析器上。
