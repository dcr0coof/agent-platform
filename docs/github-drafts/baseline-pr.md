# fix: 完善 Agent 核心可靠性、天气接口和 CLI 验证

## 问题与结果

连续工具对话超出消息窗口时，旧实现可能删除 assistant 的工具调用而保留 tool 结果；失败请求还会把半轮消息写入历史。本 PR 按完整回合裁剪，并在成功后提交对话，避免后续请求携带损坏的上下文。

同时修复天气 gzip 与旧域名配置、LLM HTTP 状态和序列化问题、计算器非法运算与溢出，补齐启动校验及 CLI 取消/超时处理。

## 关联 Issue

Closes #1

已发布为 [PR #10](https://github.com/dcr0coof/agent-platform/pull/10)。

## 实现与验证

- 记忆切片复制与锁；同一 Agent 串行运行、可取消等待；工具异常作为结果返回。
- 显式发送零温度和空内容，限制 HTTP 响应大小，明确报告状态码。
- 天气使用专属 Host 与头部鉴权，支持 gzip，校验城市和查询类型。
- 新增回归测试和真实 CLI + 本地 HTTP 服务集成测试，覆盖工具调用、清空、EOF、帮助和超长输入。
- 本地 `go test ./...`、`go vet ./...`、`go build ./...` 通过。
- Linux CI 配置竞态检测；本机缺少 CGO/C 编译环境，尚未执行远端 CI。

## 配置与限制

天气用户需额外配置 `AGENT_WEATHER_BASE_URL`。摘要尚未实现，启用会明确报错。记忆窗口是保留完整回合的软限制；真实模型和天气账户未联调，工具外部副作用不能随失败回合回滚。
